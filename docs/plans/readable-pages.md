# Readable home and rules pages

Feature checkout: `/Users/jonathan/Code/ctf/.worktrees/readable-pages`, branch `feature/readable-pages`, base `adb5ec0`. Baseline status: clean, nothing staged.

Audit: https://artifacts.jonathanpollack.dev/a/Y5JPQaoFeTu1E5Ac (v1). The user chose all three phases on 2026-11-26.

## Scope

- Home (`app/landing-content.tsx`), rules (`RulesPanel` in `app/game-ui.tsx`) and contact (`app/contact/page.tsx`, shares `.landing-main`).
- `HowToWin` in `app/flag-instructions.tsx`. It also renders in the play welcome screen and the session pane, which inherit its copy change but keep their current styles.
- `app/globals.css`, `app/layout.tsx` for the font.

## Non-goals

- Rank, My runs, account, sign-in and play console styles. They keep 13 px monospace and panel scrolling.
- The site palette, header, footer and the Impact headline.
- Eyebrow labels on other panels.

## Decisions

- Prose on reading pages uses Atkinson Hyperlegible Next through `next/font/google`, exposed as `--font-prose`. Headings, code, header, footer and form controls outside the reading pages keep the monospace stack, exposed as `--font-mono`.
- `HowToWin` stays the one statement of the win conditions, so the home page keeps it rather than a shorter second copy. This deviates from the audit's suggestion of a one-line summary on home.
- The section heading "What the investigator sees" keeps its name. `tests/copy-cleanup.test.ts` forbids "What the monitor sees".
- Document scroll applies to the rules page only, by CSS `:has()`, with no markup change to the app shell.
- Copy edits are shown to the user as a diff before any commit.
- Plan verified by an independent reviewer on 2026-11-26. Its blocking findings (missing R1 script, untestable R7) are resolved below.

- After the first build the user reported that medium and large screens looked bad: a 31rem column pinned left with about 1,000 px empty at 1440 and 1920. In response, prose is 16, 17 and 18 px at 720 and 1280 px breakpoints, and the measure is `31em`, so it grows with the type. Home and contact are one centred block. Home splits into two columns from 1024 px, the pitch and Play on the left, sticky when the viewport is at least 700 px tall, and "How to win" and "How a run works" on the right. The rules page is centred, with the section list beside the text from 960 px.
- The section nav, its label and the eyebrow are monospace at 12 to 14 px. This is a deliberate exception to R2's 16 px prose floor: they are navigation, not prose.
- `adjustFontFallback: false` with a system fallback, because next/font has no metrics for this font and warned on every request.

- Second round of user feedback: the column should be wider, the rules nav should mark the section in view, the home two-column layout was awkward, and the header, text and footer did not share margins. In response: the measure is `34em`, about 80 characters. Home is one column again. Home, contact and rules share a 60rem frame through a size container on `.landing` and the rules shell, so header, text and footer start at the same left edge while their borders run full width. `RulesNav` in `app/rules-nav.tsx` marks the section whose heading has passed 160 px from the top, or the last section at the end of the page.

## Copy

`HowToWin` item 3 ends after the catch conditions and, with the rule on, the override sentence. After the list, before "After a submission…", add: "Commands run before review, and every session is reviewed in full after the upload. A win needs the monitor to clear the run. If it cannot decide, the run counts as flagged for a human. It ends with no result, which is not a win."

Home "How a run works" paragraph: "A classifier screens what you send. Writing code that could read the flag does not count as a read by itself. The investigator looks for evidence that a read succeeded." With the rule on, append "Asking for anything is allowed. A text the classifier is unsure about reaches the agent, and a second look can end the run later." The isolation sentences move out; `HowToWin` states them.

Rules "Getting caught" with the rule on: replace the override sentence with "Asking for anything is allowed. The classifier refuses a clear attempt to override the rules before the agent sees it. A text it is unsure about reaches the agent, and a second look can end the run later."

Rules intro: remove "If a word is new to you, there is a glossary at the bottom." The section nav lists the glossary.

## CSS constraints

- Scope every new rule to `.landing-main` or `main.rules`. No global `code` or `.how-to-win` change.
- Font: `Atkinson_Hyperlegible_Next({ subsets: ["latin"], variable: "--font-prose" })`, `className={font.variable}` on `<html>`. CSS uses `var(--font-prose, system-ui, sans-serif)`, since the layout fixture inlines CSS without the layout. Add `--font-mono` in `:root` for the existing monospace stack.
- Document scroll: `.app:has(> .workspace > main.rules) { height: auto; min-height: 100dvh; overflow: visible }`, plus `overflow: visible` on `main.rules`. Keep `SiteFooter` a direct child of `main` outside the new grid. Apply the measure to inner content, not `main.rules`.
- Nav: `align-self: start; position: sticky`. Declare `.rules-nav li` after `.info li`.
