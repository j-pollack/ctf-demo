## Problem

Monitor reviews are admitted against the same run budget as the agent (`reserveInference` in `lib/games.ts:884`, the pre-check in `lib/monitor-classifier.ts:76`). A review that cannot reserve its ceiling is refused with a `GameError`. The worker records that as an `error` (`lib/monitor-worker.ts:197`). Three errors pass within about six seconds and the job becomes `unresolved` (`lib/monitor-jobs.ts:181`). Only a later append requeues an `unresolved` job, and a run that is finalizing or ended accepts no append. `claimAsyncFinalization` requires every job caught up, so the run never finalizes and a correct submission stays unconfirmed. No false win is possible.

Three triggers were traced by reading the code. None is covered by a test.

- The run is near its budget when the last response ends.
- A sibling session, or a call that was cut off, holds a reservation.
- An aborted investigator call keeps its own reservation, which starves the retries.

Production data from the last 14 days, read from a preview branch of the production database on 2026-11-14: 16 transcript reviews and 78 investigator calls. One call reserves $0.073 at the median and $0.141 at most. A review settles at $0.019 at the median and $0.030 at most. The reservation is far above the settled cost because input is reserved at one token per byte and twice the input rate.

## Decision

The user chose on 2026-11-14 to exempt monitor reviews from the run budget, over a budget floor.

A review that the worker runs under a job claim is admitted without the per-run budget check. Its reservation and settled cost are still recorded on the run. The daily cap still applies. A run's spend can end above its budget by the cost of the reviews that were outstanding when the agent could no longer be admitted.

Sizing. An exempt call skips the per-run `requestAllowance` and its refusal (`lib/games.ts:943`) and reserves its full wanted output. The daily-cap allowance and refusal stay. The classifier skips only the run-budget part of its pre-check (`lib/monitor-classifier.ts:76`) and keeps the daily-cap part.

Overage ceiling. The exemption applies only while `spent < budget + MONITOR_OVERAGE_MICRODOLLARS`, a new constant of 250,000. It counts settled spend only, because reservations of concurrent reviews or of an aborted call would otherwise refuse ordinary reviews. One function evaluates the condition for both admission sites. Above it the review meets the ordinary run-budget check. Sessions per run are not capped, so without a ceiling a player could line up many sessions with unreviewed content and spend the daily cap, which all players share. Each call checks settled spend before it reserves, so one run's overage is bounded at $0.25 plus the calls in flight when the ceiling is crossed.

Agent admission changes in one way. Today an agent request over budget gets status 402, which marks the run exhausted, only when nothing is reserved (`lib/games.ts:950`). With a reservation outstanding it gets status 400 and the run stays active. The instruction is saved before admission and enqueues a review (`lib/runner-async.ts:263`), so a player over budget could repeat refused instructions while an exempt review holds a reservation, and each cycle would buy a review at no cost to the player. An agent request now gets 402 when `spent >= budget` and no agent reservation is outstanding on the run. Status 400 remains for `spent < budget` with too little available. It also remains while another session's agent call holds a reservation, so a refused instruction cannot end the run under a paid call that is still in flight. That exception was added in the corrective cycle. Reviews bought by instructions refused in that window are bounded by the overage ceiling.

The eval harness in `scripts/flag-read-eval-live.ts` passes a job claim and enforces its stop budget through run-budget admission of reviews. The exemption must not reach it. The worker opts in explicitly through an optional readonly field `runBudgetExempt` on `MonitorJobClaim`. `lib/monitor-worker.ts` builds `{ ...claim, runBudgetExempt: true }` after claiming. `claimMonitorJob` never sets it. The plan verifier traced that this object reaches both admission sites unchanged and that `assertMonitorJobClaim` ignores the extra field. The exemption requires `role === "monitor"` and the field.

## Accepted limits

- A run's worst-case spend is its budget, plus agent reservations already admitted when reviews push settled spend past the budget, plus the $0.25 ceiling, plus the review calls in flight when the ceiling is crossed. Agent reservations are not counted in the ceiling, because an agent hold without a generation id would then block reviews for up to 24 hours.
- A run that is already exhausted or ended still has its leftover jobs reviewed at real cost, up to the ceiling. Before this change those reviews were refused and the jobs became `unresolved`. The instruction that exhausts a run is saved before admission, so each exhaustion buys one more review.
- B4 and B8 are refused at the classifier pre-check, so the daily-cap and ceiling branches inside the exempt `reserveInference` path are not exercised by a test. Both sites call one function.

## Non-goals

- The reservation formula and the frozen investigator policy.
- The unused 20-second retry delay in `RETRY_DELAYS_MS`.
- A recovery path for `unresolved` jobs.
- Refusing a fork of a run whose spend is at or above its budget. Forking is disabled.
- The reverse case, where a monitor reservation lowers the agent's allowance.
- Reservations without a generation id that hold finalization for up to 24 hours.
