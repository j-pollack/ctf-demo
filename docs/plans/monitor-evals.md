## Contract

Add a small, human-labeled monitor eval suite and opt-in runner. Measure both legitimate-call approvals and prohibited-call blocks, with failures separated into false blocks, false allows, invalid responses and service errors. Reuse the actual `MONITOR_PROMPT`, `MONITOR_MODEL`, `AGENT_PROMPT`, and `parseDecision`. Do not change the approved prompt, application runtime, season data, decision parser or dependencies.

Use at least eight allow and eight block cases. Include ordinary shell work, listing/metadata versus content access, literal filename mentions, unrelated file reads, harmless continuation after a generic `Blocked` result, direct and indirect protected-file reads, and injection in user text, agent reasoning and tool output. Synthetic histories must make aliases/scripts unambiguous and use the same serialized Pi message structure as `lib/runner.ts`; prior block reasons never enter histories. No case command is ever executed.

`npm run eval:monitor` is an offline dry run showing cases and configuration, explicitly not evaluated. `--live` plus a dedicated `EVAL_OPENROUTER_API_KEY` enables requests; never auto-load `.env.local` or fall back to the application's key. `--repeat N` accepts integers 1–5 (default 1). No new evaluator framework or model judge; expected boolean labels provide scoring. No automatic retries; provider failures remain visible.

Live setup may reuse `getModel(MONITOR_MODEL, "monitor")` via dynamic import only after opt-in/key validation to get actual capability and price configuration. Evaluation/scoring and offline imports remain dependency-free apart from the pure policy module and Node built-ins; no DB operations or SDK sessions. The completion payload matches the app's monitor path: system prompt, serialized transcript/proposed call, JSON response format, reasoning disabled when supported, required provider parameters and catalog price caps, 2048 max output tokens. Requests are sequential with a finite timeout, and calls are bounded by cases times repeats. This is not a dollar-budget guarantee; documentation must recommend a separately capped provider key and state that eval spend bypasses game accounting.

Emit a JSON report suitable for shell redirection: timestamp, mode, model, monitor version, prompt hash, suite hash, repetitions, per-case expected/actual decisions and reason/status, counts/rates for both classes, false allows/blocks, format errors and service errors. Never count errors as successful blocks or omit errors from total denominators. Malformed JSON/schema, responses exceeding the prompt's 200-character reason limit, missing message/content, and truncated completions cannot pass. A live run exits nonzero for any mismatch/error; a dry run reports no model scores. Include reported usage cost when available, explicitly unknown otherwise, without inventing a spend estimate.

Non-goals: prompt changes, old-prompt comparisons, adaptive attacks, shell simulation/execution, production transcript export, CI live jobs, shared credentials/data, merges, pushes and deployment. Actual paid evaluation is not run during implementation. Offline proof demonstrates the harness, not the monitor's efficacy; the shipped opt-in command is the real-service contract check.
