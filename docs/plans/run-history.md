## Scope and decisions

Add a My runs tab for guests and members, newest-first paginated summaries, opening full persisted transcripts using the existing Entry renderer and private detail handler. Preserve `GET /api/games` latest semantics. Existing stored rows appear without migration. Member ownership works across sessions/devices; guest history is only recoverable with its anonymous session cookie. Existing Better Auth account linking already transfers every run; change copy, not linking behavior.

Use an additive private `/api/games/history` endpoint. Choose bounded keyset pagination (20 default, max 50), order `(created_at DESC,id DESC)` with a validated opaque cursor carrying exact database timestamp precision and UUID. Explicit summary column selection joins season only; do not query events, messages, secrets, owner IDs or reconcile inference for listing. Malformed/oversized cursor or invalid limit is 400; absent session is 401; owner always comes from real session. Duplicate query parameters should be rejected rather than ambiguously interpreted.

Keep live run state separate from historical selection/detail. Historical detail never receives SSE updates; only an explicit Continue action which re-fetches/rechecks active status and unexpired season at action time may return to play. If that response is ended/expired, remain read-only. Completed/expired history is read-only. Pending billing displayed separately. Guard old detail/list/latest/poll/SSE completions against selection and account changes; abort or generation checks are acceptable. No in-flight historic detail may replace a new run. Account loss/change clears private displayed data and cancels/invalidates prior callbacks.

No new tables, infrastructure, auth mechanism, filters, charts, exports, aggregate stats or migrations. No recovery claim after lost guest cookies. Existing legacy season name/null dates must display. Empty/no-session browsing cannot create an anonymous session, environment or paid inference.

### Explicit navigation contract and persistence

- Canonical run URL is `/runs/<id>`; `/runs` is My runs. `/` is the initial Play landing; existing Rank/Rules receive `/rank` and `/rules` leaves solely so browser navigation has one source of truth. Native Next links/router only.
- Keep one GameUI instance in a shared `(game)` layout across those routes. Root HTML/metadata layout stays unchanged. Move existing server season/model initialization into that shared layout; explicit empty page leaves define only these URLs (unknown routes still 404).
- Remember a Play ID separately from the currently streamed/continued `game`. Set it once from the private latest endpoint on authenticated mount and after successful New run. History selection, Back/Forward and Continue of an older active run do not change it. Play navigates to that remembered ID (or `/` when absent). New-run failure changes neither remembered target nor URL.
- Reload/new tab has no in-memory state: recover remembered Play ID from existing private latest endpoint. This means latest persisted created run across devices, not historical URL, becomes Play's target. No local/session storage, cookies or schema are added. The deep-linked run remains viewed even while latest loads; latest must never redirect a non-root URL. Root Play initialization may replace `/` with the remembered run URL.
- `/runs/<id>` shows the matching currently loaded live game when appropriate; otherwise fetches that private historical detail and shows existing read-only renderer/explicit Continue. Direct load first reauthorizes the requested ID. If it is the latest current run, show its usual live/read-only-by-status view; other active runs require explicit Continue. Ended/expired runs never acquire a composer.
- Explicit Continue may load an older active run into the existing live execution slot but retains the remembered Play ID. Returning to Play loads the remembered run when needed. While a stream is busy, URL navigation may display another run read-only but must not replace its underlying execution slot, invalidate its finalization, or strand busy state. An idle Play click explicitly loads/activates its remembered target using a fresh private GET, unlike an ordinary historical click. If Play is clicked while another run streams, show the remembered target read-only and leave it read-only after the stream finishes; no deferred automatic activation. A subsequent explicit Continue or Play while idle may activate it, with the existing fresh status/season recheck. Mere historical navigation never changes the live slot. Initial latest recovery sets the remembered ID independently of whether its payload is still eligible to replace the execution slot, but never overwrites a newer successful POST target.
- List/selected detail and visible metadata must match the URL, including on reload, Back/Forward and failed/unauthorized routes. Detail errors do not fall back to a different latest run. Clear previous detail promptly while the next ID loads. Account change clears all private state and remembered ID; reauthorize any remaining URL. No-session deep links do not create auth or environments.
- Date is guaranteed in summaries; a deep link with no loaded summary may omit date rather than query full history or widen the detail API. All persisted transcript/model/season/spend/status fields remain present.
