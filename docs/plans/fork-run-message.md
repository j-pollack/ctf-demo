## Contract

Add Copy and Fork beneath every agent entry (Copy is not currently implemented). Fork opens the existing native dialog, identifies/previews the selected response, and explicitly confirms creating a new run with history **through and including** that response. Cancel performs no mutation. Successful confirmation selects the new run, retains exact visible history prefix with new event IDs, preserves the matching Pi conversation prefix, clears the prompt, and waits for the next instruction. No automatic inference or command replay.

A fork is a normal new run: current season/monitor, fresh isolated environment and unique secret, standard guest/member budget, existing start quotas and concurrency limits. The original transcript/messages/accounting stay unchanged; its active lifecycle ends under the existing one-active-run-per-owner rule. The user explicitly confirmed transcript-only semantics after discussing Sprite checkpoints. The confirmation must say: “Only the transcript is copied. Filesystem and VM state are not preserved; the fork starts in a fresh environment.” It also discloses that the current run ends, that a new secret is created, and that commands are not replayed. No VM/filesystem snapshot, history browser, automatic tool continuation, schema migration, new dependencies, changes to billing admission, or live services.

Use the selected event's successful assistant `turn` to locate the exact Pi prefix: the runner increments turns only for non-error/non-aborted assistant messages. Copy system/user/assistant/prior tool messages through that successful assistant, never results of its tool calls or later messages. Reuse `repairMessages` on continuation to resolve pending calls with the existing unknown-execution result rather than executing old tools. Fail closed if the persisted boundary cannot be found. Validate source-wide successful assistant count against stored turns and the agent-event sequence (consecutive turns 1..N and matching message models/text); gaps, duplicates or mismatches reject before provisioning. Inherit the selected event's persisted model, not the latest source model. Preserve inherited turns and blocked-event count; inference/token/spend counters start at zero for new resources, no duplicate charges or settlement records.

Server input is source run ID + positive safe-integer event ID, not a client-provided transcript/model/turn. Authenticate and check Origin/body via existing helpers; verify both source ownership and event membership/kind. Lock/snapshot source and owner active rows inside start admission transaction, reject in-progress source/current runs, select the matching prefix, seed child messages/events inside the creation transaction before activation. `claimGame` must not race snapshot/replacement; lock actual source/active rows, not mocked decisions. Revoke lease/lease_until when ending replaced runs, and revoke the source lease even if an expired runner remains, so id+lease writes cannot mutate the copied source after admission. Assert both race outcomes and a stale writer denial. Existing cleanup semantics and provisioning failure handling are preserved; failures surface in dialog without replacing displayed run. Provisioning failure can end the parent under existing start semantics; refresh the displayed parent after failure so it never incorrectly appears runnable. Reject malformed/non-agent/missing/foreign/unmappable boundaries before provisioning a Sprite or ending the original active run. Concurrent starts retain normal guarantees.
